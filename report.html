Часть 1. Теория

1. Что такое СУБД и зачем она нужна, почему не хранить всё в Excel/файлах?

СУБД (Система Управления Базами Данных) — это комплекс программного обеспечения для создания, хранения, обработки и управления данными. Она обеспечивает надежность, безопасность и многопользовательский доступ.

Использование Excel или простых файлов не подходит для серьезных систем по следующим причинам:

  • Конкурентный доступ: Excel блокирует файл при открытии одним пользователем, СУБД позволяет работать сотням пользователей одновременно.
  • Транзакции и атомарность: СУБД гарантирует, что операция выполнится либо целиком, либо не выполнится вовсе (принцип ACID). В файлах при сбое данные могут остаться в поврежденном состоянии.
  • Целостность данных: СУБД контролирует типы данных, уникальность и связи между таблицами (через первичные и внешние ключи).
  • Масштабируемость и производительность: СУБД используют индексы и кэширование для мгновенного поиска по миллионам записей. Excel «зависает» на десятках тысяч строк.
  • Разграничение прав доступа: Гибкая настройка ролей (кто может читать, кто изменять).

2. Какие СУБД знаешь, как их можно классифицировать?

Реляционные: PostgreSQL, MySQL, Oracle Database, Microsoft SQL Server, SQLite.

Документные (NoSQL): MongoDB.

Ключ-значение (Key-Value): Redis, Memcached.

Колоночные: ClickHouse, Vertica.

Классифицировать их можно по модели данных (реляционные, документные, графовые), по архитектуре (клиент-серверные и встраиваемые), по типу лицензии (коммерческие, open-source).

3. Что такое реляционная модель?

Это логическая модель данных, основанная на математической теории отношений (реляционной алгебре). Данные представлены в виде таблиц (отношений), состоящих из строк (кортежей) и столбцов (атрибутов). Связи между таблицами реализуются через ключи (первичные и внешние).

4. Чем первичный ключ отличается от внешнего?

  • Первичный ключ (Primary Key, PK): уникально идентифицирует каждую строку в своей таблице. Не может содержать NULL.
  • Внешний ключ (Foreign Key, FK): поле (или набор полей) в одной таблице, которое ссылается на первичный ключ в другой таблице. Обеспечивает ссылочную целостность (нельзя добавить запись с несуществующим ID). Может быть NULL (если связь необязательная).

5. Какие бывают типы связей? Как реализовать «многие ко многим»?

Типы связей: Один к одному (1:1), Один ко многим (1:N), Многие ко многим (N:M).

Связь «Многие ко многим» реализуется через промежуточную (связующую) таблицу, которая содержит внешние ключи к обеим связываемым таблицам. Часто в такой таблице создается составной первичный ключ из этих двух полей.

6. Что такое нормализация и зачем она нужна?

Нормализация — это процесс организации данных в таблицах с целью минимизации избыточности и предотвращения аномалий при вставке, обновлении и удалении данных. Основные нормальные формы:

  • 1НФ: атомарность значений (нет массивов в ячейках), нет повторяющихся групп.
  • 2НФ: 1НФ + отсутствие частичной зависимости неключевых атрибутов от части составного ключа.
  • 3НФ: 2НФ + отсутствие транзитивных зависимостей (неключевые поля зависят только от ключа).

7. Когда денормализация оправдана?

Денормализация (намеренное добавление избыточности) оправдана в следующих случаях:

  • Для ускорения сложных аналитических запросов (отчеты, OLAP), где чтение преобладает над записью.
  • Для снижения количества JOIN-ов в высоконагруженных системах.
  • При кэшировании агрегированных данных (например, хранение общего баланса счета прямо в таблице клиентов).

8. Чем WHERE отличается от HAVING?

WHERE фильтрует строки до группировки данных. HAVING фильтрует сгруппированные данные после применения агрегатных функций (SUM, COUNT и т.д.). В одном запросе могут использоваться оба оператора.

9. Какие виды JOIN знаешь?

  • INNER JOIN — возвращает только совпадающие строки в обеих таблицах.
  • LEFT JOIN (или LEFT OUTER JOIN) — все строки из левой таблицы + совпадения из правой (если нет — NULL).
  • RIGHT JOIN — все строки из правой таблицы + совпадения из левой.
  • FULL JOIN — все строки из обеих таблиц.
  • CROSS JOIN — декартово произведение (все возможные комбинации строк).

10. Чем DELETE, TRUNCATE и DROP отличаются?

Команда Что делает WHERE Транзакции Триггеры
DELETE Удаляет строки (можно выборочно) Да Можно откатить (DML) Срабатывают
TRUNCATE Быстро очищает всю таблицу Нет В некоторых СУБД нельзя откатить (DDL) Не срабатывают
DROP Удаляет таблицу целиком (структуру и данные) Нет Нельзя откатить (DDL) Не срабатывают

11. Что такое NULL и как с ним работать?

NULL — это специальное значение, обозначающее отсутствие данных (неизвестность). Это не ноль и не пустая строка.

Особенности работы:

  • Любая арифметическая операция с NULL дает NULL.
  • Сравнение NULL = NULL дает NULL (не TRUE). Для проверки используют IS NULL или IS NOT NULL.
  • Агрегатные функции (SUM, AVG, COUNT(column)) игнорируют NULL. Исключение: COUNT(*) считает все строки.
  • Для замены NULL на значение по умолчанию используют функции COALESCE(), IFNULL(), NVL().

12. Что такое индекс, есть ли у него минусы?

Индекс — это структура данных (обычно B-tree), которая ускоряет поиск и сортировку строк по определенному столбцу, работая по принципу оглавления в книге.

Минусы:

  • Замедляют операции вставки, обновления и удаления (так как индекс нужно перестраивать).
  • Занимают дополнительное место на диске.
  • Требуют периодического обслуживания (дефрагментации/перестроения).

13. Что такое транзакция?

Транзакция — это последовательность операций с базой данных, которая выполняется как единое целое. Она должна обладать свойствами ACID:

  • Atomicity (Атомарность): всё или ничего.
  • Consistency (Согласованность): переход из одного корректного состояния в другое.
  • Isolation (Изолированность): параллельные транзакции не влияют друг на друга.
  • Durability (Долговечность): результаты зафиксированной транзакции сохраняются даже при сбое.

Управление осуществляется командами BEGIN, COMMIT, ROLLBACK.

Часть 2. SQL-задачи (PostgreSQL)

Схема БД:

clients      (client_id PK, full_name, city, registered_at DATE)
accounts     (account_id PK, client_id FK, currency, opened_at DATE, closed_at DATE NULL)
transactions (tx_id PK, account_id FK, tx_date TIMESTAMP, amount NUMERIC, tx_type)  -- tx_type: 'in' / 'out'

1. Клиенты из Новосибирска, зарегистрированные в 2025 году, по дате регистрации

SELECT client_id, full_name, city, registered_at
FROM clients
WHERE city = 'Новосибирск'
  AND registered_at >= DATE '2025-01-01'
  AND registered_at <  DATE '2026-01-01'
ORDER BY registered_at;

2. Количество открытых счетов в каждой валюте

SELECT currency, COUNT(*) AS open_accounts
FROM accounts
WHERE closed_at IS NULL
GROUP BY currency
ORDER BY currency;

3. Имя клиента и общая сумма входящих транзакций

SELECT c.client_id, c.full_name, COALESCE(SUM(t.amount), 0) AS total_in
FROM clients c
JOIN accounts a ON a.client_id = c.client_id
LEFT JOIN transactions t ON t.account_id = a.account_id AND t.tx_type = 'in'
GROUP BY c.client_id, c.full_name
ORDER BY total_in DESC;

4. Клиенты без единого счёта (анти-джойн)

SELECT c.*
FROM clients c
LEFT JOIN accounts a ON a.client_id = c.client_id
WHERE a.account_id IS NULL;

5. Клиенты, у которых больше двух счетов (HAVING)

SELECT c.client_id, c.full_name, COUNT(a.account_id) AS accounts_cnt
FROM clients c
JOIN accounts a ON a.client_id = c.client_id
GROUP BY c.client_id, c.full_name
HAVING COUNT(a.account_id) > 2;

6. Поиск задвоенных транзакций (дубли)

SELECT account_id, tx_date, amount, COUNT(*) AS dup_cnt
FROM transactions
GROUP BY account_id, tx_date, amount
HAVING COUNT(*) > 1
ORDER BY dup_cnt DESC;

7. Со звёздочкой: Топ-3 клиентов по сумме исходящих транзакций в каждом месяце

WITH monthly AS (
    SELECT c.client_id, c.full_name, DATE_TRUNC('month', t.tx_date) AS month, SUM(t.amount) AS out_sum
    FROM clients c
    JOIN accounts a ON a.client_id = c.client_id
    JOIN transactions t ON t.account_id = a.account_id
    WHERE t.tx_type = 'out'
    GROUP BY c.client_id, c.full_name, DATE_TRUNC('month', t.tx_date)
),
ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY month ORDER BY out_sum DESC) AS rn
    FROM monthly
)
SELECT month, client_id, full_name, out_sum
FROM ranked
WHERE rn <= 3
ORDER BY month, out_sum DESC;

Фикстура для подключения к БД с явным указанием пути к .env и флагом override=True (чтобы избежать конфликтов с переменными окружения Windows).

import os
from pathlib import Path
import pytest
import psycopg
from dotenv import load_dotenv

load_dotenv(dotenv_path=Path(__file__).parent / ".env", override=True)

def get_conn_params():
    return dict(
        host=os.getenv("PG_HOST", "localhost"),
        port=int(os.getenv("PG_PORT", "6432")),
        user=os.getenv("PG_USER", "testuser"),
        password=os.getenv("PG_PASSWORD", "testpass"),
        dbname=os.getenv("PG_DB", "testdb"),
        connect_timeout=5,
    )

@pytest.fixture(scope="session")
def db_conn():
    with psycopg.connect(**get_conn_params()) as conn:
        yield conn

test_db.py

import psycopg
import pytest
from conftest import get_conn_params

def test_connection_ok(db_conn):
    """Подключение установлено, SELECT 1 возвращает результат."""
    with db_conn.cursor() as cur:
        cur.execute("SELECT 1")
        row = cur.fetchone()
    assert row is not None
    assert row[0] == 1

def test_now_query(db_conn):
    """Простейший запрос из ТЗ: select now()."""
    with db_conn.cursor() as cur:
        cur.execute("SELECT now()")
        row = cur.fetchone()
    assert row is not None
    assert row[0] is not None

def test_bad_password_fails():
    """Негативный кейс: с неверным паролем подключение падает."""
    bad = get_conn_params()
    bad["password"] = "wrong_password"
    with pytest.raises(psycopg.OperationalError):
        with psycopg.connect(**bad):
            pass
